# 安全政策（SECURITY）

作者：**海风（kele551）** · 仓库：https://gitee.com/kele551/hotnews

hotnews（热点新闻检索）是一个**只在本机运行**的新闻聚合器：默认只监听 `127.0.0.1`，
处理的内容是各站公开的新闻标题、摘要与链接，不涉及用户账号与隐私数据。
即便如此，**升级通道**和**本地接口**仍然值得认真对待 —— 这个文件说明漏洞该怎么报、
多久能得到回应、哪些算、哪些不算。

---

## 一、怎么私下报告（不要开公开 Issue）

**首选：GitHub 仓库的私密漏洞报告入口**

> https://github.com/kele551/hotnews/security/advisories/new
>
> （GitHub 仓库 → **Security** → **Advisories** → **Report a vulnerability**。
> 这条通道只有维护者可见，适合贴细节。）

**次选：站内私信。** 如果上面的入口不可用，请在 GitHub 或 Gitee 上给 `@kele551`
发**站内私信**，先用一句话说明「有安全问题想私下报告」，细节在私下对话里给。
**不要把细节写在公开 Issue、评论或群里。**

报告里请尽量带上：

- 受影响版本（页面显示的版本号，或 exe 文件属性里的 `FileVersion`）与运行方式（单文件 exe / 源码运行）；
- 影响面：能读到什么、能改什么、是否需要用户先做某个操作才会触发；
- 复现步骤或最小验证方法；
- 你希望怎么被署名（默认不署名）。

**请不要**：

- 在公开 Issue 里贴漏洞细节（可以先开一个「我发现了安全问题，已按 SECURITY.md 私下报告」的
  空 Issue 提醒维护者，但不要写细节）；
- 把未修复的漏洞细节先发给第三方媒体或投稿渠道；
- 以本项目的名义去测试任何第三方站点 —— 那不在本项目的授权范围内，
  也不是本项目能授权的事情。

## 四、哪些算（在范围内）

- 本仓库自己的代码：`app.py`、`server.py`、`updater.py`、`_ed25519.py`、`static/`、`tools/`、打包脚本；
- **升级通道**：`version.json` 的 Ed25519 签名校验、升级包的 SHA256 与尺寸校验、
  替换时机与失败回滚（实现见 `updater.py`，策略见 [CODE_SIGNING_POLICY.md](CODE_SIGNING_POLICY.md)）；
- **本地接口鉴权**：`/api/quit`、`/api/update/install`、`/api/autostart` 的本机令牌（`X-HN-Token`）
  与同源校验（Origin / Referer + 客户端地址必须是回环）；
- **图片代理 `/img`**：地址闸门（只允许 http/https、常用端口、解析结果必须全是公网地址）
  与来源域名白名单；
- **产物与发布流程**：能否让用户装到一个「不是本仓库源码构建出来的」exe，
  或者跳过 SHA256 / 签名校验拿到替换权限。

## 五、哪些不算（范围外，请别报给这里）

- **第三方新闻源站自身**的问题（挂马、接口越权、内容侵权等）—— 请找站方，
  聚合相关的问题可以走普通 Issue；
- 你在 `config.json` 里自己填的第三方服务凭据（翻译后端的 `appid` / `secret` / `auth_key`）
  泄露或被滥用；
- 你主动用 `--host 0.0.0.0` 把页面暴露到局域网或公网之后带来的风险；
- 操作系统、浏览器，以及依赖包（fastapi / uvicorn / httpx / feedparser）自身的漏洞 ——
  请报给上游，本项目会跟进升级；
- 新闻内容的真实性、版权与观点 —— 见 README 的免责声明，有异议请提 Issue。

## 六、已知的设计取舍（不是漏洞，报之前先看一眼）

1. **默认只监听 `127.0.0.1`。** 用 `--host 0.0.0.0` 之后局域网可以浏览页面，
   但「退出程序 / 立即更新并重启 / 开机自启」这三个有副作用的按钮**只允许本机操作**，
   非本机访问会拿到 403。这是有意的取舍：只读浏览可以放开，能改本机状态的操作不放开。
2. **`/img` 的白名单是「来源白名单」而不是「内容白名单」。** 它只保证不去请求未登记域名，
   不保证被代理的图片内容本身安全（图片来自源站）。真正挡住内网探测的是地址层闸门：
   私网、回环、链路本地、组播地址一律拒绝，域名解析失败按拒绝处理。
3. **升级是 fail-closed 的。** 拿不到期望的版本信息、`sha256`、下载地址，或校验不符时，
   程序**拒绝替换**并保留旧版 —— 宁可这次不升级，也不冒装错包的风险。
4. **`mefcl` 源的访问方式**：该站有站方自己的访问校验流程，程序按站方流程取到访问凭据后
   正常请求首页；全程不涉及登录态、不读取付费内容（见 README 的数据源说明与免责声明）。
5. **程序会联网**：抓取新闻源、检查更新、以及可选的机器翻译。
   抓取范围仅限各站公开接口与首页，每个源每轮刷新最多请求一次（默认 10 分钟一轮），不并发压站。
