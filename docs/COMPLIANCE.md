# 合规声明（COMPLIANCE）

> 本文件的合规口径与《合规守法》条款一致（维护者工作区章程 §9）。  
> 作者：海风（kele551） · 仓库：https://gitcode.com/kele551/hotnews  
> 最近更新：2026-10-09

**一句话**：本工具是**个人学习用的新闻标题聚合器** —— 只把各新闻网站**公开的标题、摘要与原文链接**
汇到一个页面上，**不复制、不存储、不转载正文**，不提供任何新闻采编发布服务。

---

## 1. 聚合边界

| 项 | 我们做什么 | 我们不做什么 |
|---|---|---|
| 内容 | 只取**公开的标题 / 摘要 / 原文链接 / 题图地址** | ❌ 不抓取、不保存、不再分发正文全文 |
| 跳转 | 每条都保留**原文链接**，点击直达来源网站 | ❌ 不做站内阅读页、不做镜像站 |
| 版权 | 新闻内容**版权归原网站所有**，页面上不作任何署名替代 | ❌ 不声称拥有内容、不二次授权 |
| 商业 | 完全免费、无广告、非商业用途 | ❌ 不收费、不带推广 |
| 移除 | 权利人可通过 **Issue** 要求移除来源，核实后立即移除 | ❌ 不与被要求移除的来源继续拉扯 |

## 2. 抓取边界

- 抓取对象**只有各站公开的 RSS / 官方 JSON 接口 / 站点首页**，**不使用任何登录态**、不读取付费内容。
- **频率克制**：正常一轮刷新里每个源最多请求 1 次（默认 10 分钟一轮）；
  启动时的两段式预热（快速版 + 完整版）与失败重试会让个别源在一轮里被请求 2~3 次
  —— 前者是为了首屏尽快有内容，后者是网络抖动后的自愈，都不是循环打点。
  文章页补图有单轮条数上限（国内 96 条、国际 48 条，且**按来源轮流分配**，见第 7.2 节）；
  不做并发压站。
- 请求头：按源站要求带常规浏览器 UA 与来源站点（Referer）信息，以符合各 CDN 的访问策略；
  站点若通过 `robots.txt` 或接口说明表达不希望被访问，**会按要求移除该来源**。
- 已知会用到站方自己的访问校验流程（如 mefcl 的 `ge_js_validator` cookie）：**只是按站方校验流程
  正常取用公开页面**，不涉及任何登录态或权限提升。
- 抓取失败一律**不影响**其它来源；抓不到就不展示，不做任何补偿性造假（时间一律取源站真实值）。

## 3. 隐私与数据

- **不采集、不上传**任何用户数据：没有账号、没有埋点、没有遥测、没有云端。
- ⚠ **唯一会把"内容"发往第三方的路径：可选的机器翻译，默认关闭。**
  打开后（`config.json` 里 `translate.enabled = true`），国际栏的**英文条目标题与摘要**
  会经第三方翻译服务转成中文：
  - 默认后端 **MyMemory**（`api.mymemory.translated.net`，**境外**，免费免 key）；
  - 也可改用 **百度翻译**（`fanyi-api.baidu.com`，**境内**，需自备 appid/secret）或
    **DeepL**（`api-free.deepl.com`，**境外**，需自备 auth key）。
  **发出去的只有公开的新闻标题/摘要（每条最长 300 字），不含任何用户数据、不含本机信息**；
  译文只缓存在本机（`translate_cache.json`）。
  **默认关闭**，所以新装用户与国际栏保持"零内容出网"。
  该接口（`/api/translate`）与其它有副作用的接口一样带**同源 + 仅本机 + 本机令牌**三道闸门。
- 所有配置与缓存（译文缓存、本机令牌、日志）**只落在本机**：
  `%LOCALAPPDATA%\hotnews\`、程序同级的 `hotnews.log`；卸载即随之删除。
- 对外文档**不写私人邮箱**（避免被爬虫抓取）；仓库内**不含任何令牌、密钥、签名私钥**。
- 升级通道用离线 Ed25519 私钥签名、客户端内置公钥验签；**验不过一律拒绝升级**。

### 7.1 新闻内容源的唯一例外：国际娱乐栏接入 2 家境外娱乐媒体（2026-10-11 用户拍板）

**这不是擅自破例，是用户看过实测数据后明确拍板**（选项「接 Variety + Consequence」）。

**为什么必须破例 —— 境内口径下国际娱乐的供给已被实测探到底：**

| 试过的境内源 | 实测结果 |
|---|---|
| CGTN 英文·文化分区 | 50 条（跨度 12 天）里判得出国际的**只有 6 条**；把时效窗口从 7 天放宽到 30 天，**国际条数仍是 6 条**（更早的稿子全是中国题材） |
| CGTN 西 / 法 / 阿 / 俄 四语种·文化分区 | 各 200 条，各只有 **2~3 条**娱乐，且需额外翻译小语种 |
| CGTN travel / china / video 分区 | 内容全是中国题材，无国际娱乐 |
| 中国日报 / 环球时报英文 / 新华网英文 / 人民网英文 / 中新网英文 / 中国网 | 娱乐 RSS **全部 404** |
| 国内三家娱乐源（凤凰娱乐 / 新浪娱乐 / 国际在线娱乐） | 33 条里**没有一条**真国际稿（全是飞天奖、国产剧、国庆档） |

**境外候选实测 20 家，只留下 2 家** —— 筛选标准是用户 2026-10-07 定的「每条必须有高清大图」：

| 境外源 | 条数 | 带图 | 结论 |
|---|---|---|---|
| **Variety**（好莱坞产业权威） | 10 | **10/10** | ✅ 接入 |
| **Consequence**（独立音乐媒体） | 15 | **15/15** | ✅ 接入 |
| Billboard / THR / RollingStone / NME / IndieWire | 10~12 | **0**（RSS 不带图） | ❌ 过不了带图门槛 |
| 其余 13 家 | — | — | ❌ 403 / 404 / 超时 |

**破例的四条约束（写在代码里，不是口头承诺）：**

1. **只进国际娱乐栏** —— 要闻 / 科技 / 财经 / 体育 / 热榜**一个都不碰**，境外时政新闻一概不收；
2. **主权红线过滤** `_INTL_ENT_BLOCK_RX` —— 标题出现涉台 / 涉藏 / 涉疆 / 涉港表述的一律剔除，
   不看语境（实测 25 条里命中 1 条「Taiwan's Sole Busan Competition Title」，已拦）；
3. **专用判国前置层** —— 境外娱乐源 100% 是国际内容，不走境内源那套「必须正面证明自己是国际」
   的判据（否则「Shane Gillis Drops F-Bomb on SNL」这类纯欧美娱乐稿会被误判成国内，实测 10 条误杀 6 条）；
4. **总开关 `INTL_ENT_OVERSEAS`** —— 改成 `False` 立刻回到纯境内口径，不用动判据、不用改源表。

**效果**：国际娱乐 **7 条 → 29 条**，100% 带图，无图条目 0 条。
实测记录：`logs\verify-20261011-七轮-国际娱乐接境外源.md`。

**已处置（2026-10-09）**：原先登记过一家境外出版方的中文站点，因站点未见 ICP 备案号、
与「只用境内站点」的合规口径不一致，**已从源清单中移除**（为免在仓库内重复出现第三方站点名称，此处不点名）。
它只服务「国内科技」栏目（该栏还有 IT之家 / 快科技 / 爱范儿 / 雷峰网 / 极客公园 五家境内源）。
若要严格到「运营主体也必须是境内」，把它从 `SOURCES` 里删掉即可，科技栏目仍有 5 家。

### 7.2 抓取礼貌（2026-10-09 复核）

- 并发受连接池上限约束（96 连接 / 48 保活），**不高于本机既有抓取规模**；
- 正常一轮里每个源最多 1 次请求（预热两段式与失败重试的例外见第 2 节）；
  文章页补图有单轮条数上限（国内 96 条、国际 48 条），
  且**按来源轮流分配**，不会对单一站点连续打点；
- 请求头自报身份：浏览器 UA **追加**项目标识
  `HotnewsAggregator/1.5 (+https://gitcode.com/kele551/hotnews)`（`server.py` 的 `BOT_ID`）。
  用「追加」而不是整个替换 UA，是因为实测部分源（如 mefcl）会按 UA 判断
  是否为普通浏览器访问，纯 bot UA 会被挡在门外 —— 那样等于把源打挂；
  追加式标识同样让站方在日志里认得出我们、找得到仓库、提得出移除要求；
- 失败退避：普通网络抖动重试 1 次、连接池排队超时重试 2 次，均带递增退避；
  失败只写十几秒的短负缓存，不会把「一时的抖动」记成「这个源坏了」。

### 7.3 非新闻栏目「开源热榜」的境外接口登记（2026-10-28 用户点名新增；2026-11-12 补周榜与涨速榜）

**它是什么**：页面左栏「软件」栏目里的开源三榜（2026-11-12 起不再单列一栏），用三个按钮切换三份榜。前两份来自 **GitHub
官方 search 接口**：①「近 30 天新建的公开仓库，按累计星标降序」（2026-10-28 原有）；
②「近 7 天新建的公开仓库，按**日均涨星**（累计星标 ÷ 建库天数）降序」（2026-11-12 新增，
用户要的是"上星速度快、被快速认可"的新项目）。各取前 20 条，各有一份内存 + 磁盘缓存。
③「速榜」（用户写法，即原涨速榜；2026-11-12 三修）**不来自新接口**：它是前两份榜的**并集**，按「上一批到这一批
净增了多少星 ÷ 两批间隔小时 × 24 = 星/天」排序（7 天榜 1 小时一批、30 天榜 6 小时一批，
各按自己的间隔折算；页面同时写明真实净增与间隔小时，折算值不冒充等了一整天），
能捞出「建库一周以上、最近突然加速」的项目，也避免和周榜看成同一批。
题图是 **GitHub 官方**为每个仓库现生成的那张分享卡（`opengraph.githubassets.com`，1200×600）。
日均涨星与涨速都是本机按公开字段算出来的，不额外请求任何接口。
2026-11-12 九修：桌面气泡的开源席统一为「左上角 GitHub 官方徽章 / 正文只写中文用途说明 /
涨星数字放右下角那一行 / 点「打开」直达该项目 github.com 仓库页」，三路播报（周榜换批、
10 分钟暴涨、新闻轮播固定席）共用同一套文案与跳转，不跳本机榜单页。

**为什么它不算"境外新闻源"**：这一栏不供稿给任何新闻栏目，也不产生新闻条目 ——
它不进 `SOURCES`、不参与时效收口 / 事件合并 / 国内国际分流，界面上一眼也能看出来
（标题按按钮写「开源周榜 / 开源速榜 / 开源月榜」，不再写「近 7 天新建」）。它展示的是**开源项目本身**，
不是任何机构对时事的报道或评论。但"程序会往境外发一个请求"这件事本身要如实登记，所以有这一节。

**写在代码里的七条约束（不是口头承诺）：**

1. **只取三样公开信息** —— 仓库全名、站方自己写的一句话简介、仓库地址。
   不抓 README、不下代码、不做站内阅读页，每条卡片都直达 GitHub 原页面（第 1、2 节的聚合边界照旧成立）；
2. **题材闸门 `_OSS_BLOCK_RX`** —— 仓库名 / 简介 / 站方标签 / 语言分类里命中时政、军事、情报、
   色情、恶意软件与钓鱼类词的一律不展示，宁可这一栏少几条（第 4 节"不做敏感内容二次传播"的延伸）；
3. **跳转地址只认 `github.com`** —— `_oss_link()` 按域名、协议、端口、凭据四道收口，
   站方返回别的地址就当"没有链接"，不把跳转权交给返回数据的那台服务（第 2 节的抓取边界）；
4. **低频与自报身份** —— 30 天榜 6 小时一批（`OSS_TTL`）、周榜 1 小时一批（`OSS_WEEK_TTL`，
   2026-11-12 新增）；一轮最多 2 次 search 请求 + 首屏那几张官方分享卡的预热取回，
   两份榜共用图片缓存；请求头仍带 `BOT_ID` 项目标识，站方在日志里认得出我们、找得到仓库、
   提得出移除要求。页面每 2 分钟拉的是**本机内存快照**（`/api/oss`），不产生外部请求；
   第三档涨速榜同样只由这两批快照在本机派生，**不发第三次 search 请求**；
5. **抓不到就收起那一档** —— 接口不可达、额度用尽或返回 0 条时，只收起对应的那一档，
   另一档照常显示、切换按钮仍在；不报错、不占位，新闻板块一条不受影响；
   右栏「源健康度」里 GitHub 那一行由 30 天榜维护，如实标成"成功 / 失败"；
6. **周榜的桌面播报（2026-11-12 新增）** —— 首次抓到周榜即投**一条**「本周增速第 1」，
   之后换批时若出现「新晋 / 日均涨星涨了 20% / 名次跃升 3 位」且日均涨星过阈值的项目
   再投一条；内容是公开仓库名、星标数、建库天数与一句中文说明，**左上角固定一枚 GitHub
   官方 Octocat 徽章**（Simple Icons 官方矢量路径渲染：深色圆底 + 白色猫头 + 站名，
   6 倍超采样，不再用手画的圆脸），这条单独停 **12 秒**（普通新闻轮播仍是 5.6 秒），
   与普通新闻气泡一眼可分。点击打开的是**本机这一栏**
   （`?oss=week`），不直接跳转、不占新闻轮播那 10 个名额、不采集任何用户数据；
   同一仓库 24 小时内不重播（名单只存本机、跨重启有效），两条周榜气泡至少隔 10 分钟。
7. **涨速榜的本机快照（2026-11-12 三修）** —— 为了算「净增星」，程序在
   `%LOCALAPPDATA%\hotnews\oss_speed_cache.json` 里只存三样东西：仓库全名、当时的累计星标数、
   这批数据的时刻，外加派生出来的榜单条目；**只存本机、绝不上传**，不抓 README / 代码 /
   星标用户名单，也不做任何用户画像。同一仓库 24 小时内不重复投送的「已播名单」同理。
   【2026-11-12 十一修】速榜**只列这批真实涨了星的项目**：必须有上一批星标快照可对比
   （has_speed）且净增 delta>0；绝不拿「日均涨星」这个平均数摆榜（那会和周榜变成
   同一批项目、卡片还挂一屏「待对比」）。一条真值都没有时**留空榜**，页面写明
   「正在积累首批对比数据」。两路星标基准跨重启保存在本机缓存里，不再每次重启
   归零；积累期把周榜对比间隔临时缩到 3 分钟（十七修从 15 分钟收紧）让第一份
   真榜尽快出现，出真值后恢复常态 1 小时一批，不增加长期请求量。刚升级 /
   重启时有两榜本机缓存，不等下一次网络换批（30 天榜最长 6 小时），这一步
   同样不发外部请求。
   【2026-11-12 十六修】实测 15 分钟内 GitHub 星标常一颗不动，旧版「每次换批
   无条件推进基准」会让 delta 恒为 0、速榜反复被清空；冷启动又只复用磁盘里
   has_speed=False 的旧行，重启必然又是空榜。现改为：基准只在首轮建立、本路
   确实观测到涨星、或满 `OSS_SPEED_BASE_MAX_AGE = 24 小时` 时推进，零净增批次
   保留基准让净增累积；本批无真值时**不清空速榜**，保留最近一次真实净增，
   并在页面如实标注「本批暂无新增，显示最近一次真实净增（时间）」——标注用的
   `stale` / `real_at` 也只是本机缓存里的两个字段，不新增任何外部请求或数据。
   冷启动一律用磁盘基准重算两路派生行，不复用旧的「待对比」行。速榜口径仍是
   真实净增，不摆观察榜、不掺日均平均数。
   【2026-11-12 十七修】十六修部署交接态：旧版在部署前把基准推进到当场抓的那批、
   磁盘又无历史真值，新版启动只读缓存不抓新数据，基准与缓存同批 → delta 恒 0，
   速榜仍空。只读实测确认机制已好（钉住的基准对比 GitHub 实时数据能出 3 条真值），
   卡在积累期换批间隔 15 分钟太长；把 `OSS_SPEED_SEED_TTL` 从 15 分钟收紧到
   3 分钟，让首批真值几分钟内出现，出真值后恢复 1 小时常态。仍是纯真实净增，
   不摆观察榜、不掺平均数、基准不随空批推进；GitHub 搜索接口限速 10 次/分钟，
   3 分钟一批远在限流内，不增加长期请求量。
   桌面播报除周榜换批那条外，另有一组「暴涨依次」播报：每 **10 分钟**从本机
   周榜 ∪ 速榜候选里按星/天降序依次取最多 3 条（不随机），仍不占新闻 10 席、同样带
   GitHub 徽章与 12 秒停留；有真实净增时按真实净增排，首轮没有真值时退用周榜
   日均涨星、并如实标注「周榜 · 按日均涨星排」，不冒充速榜真实增速。新闻轮播每轮
   另置顶 1 个 GitHub 开源席（开机那一轮也有），置顶那条**不额外请求**（只读本机
   三档缓存），背景用该项目 owner 头像等比完整显示、四周留深色底，不裁切不放大。
   【十二修】气泡大字必须是中文用途说明：GitHub 原始简介为空、会退化成「X 开源项目」
   这类标签的条目不进播报候选池（全池 39 条里仅 3 条），三条播报路径都优先挑有
   中文内容的；只有整池都没有中文内容时才回退兜底，保证「轮播必出开源」不被破坏。
   【十三修】中文用途说明不许截半句：括号只整段删除（不砍主句后半）、顿号并列的
   「在 iPhone、iPad 和 Mac 上…」保留完整句；收口只在「≥6 汉字、末尾不悬空虚词」
   的完整边界，剥英文产品名前缀只在整段开头做一次（不误删句内英文名词）；短片段
   与标签式兜底都不进播报候选池。真实缓存全池 39 条体检 0 条半句残缺。
   【十四修】**网页卡片描述行**与气泡分开定口径：卡片原先整段照抄内部 `desc`，
   开头「GitHub 开源周榜 · 语言 · 日均涨星 N」把中文用途挤到后面并被单行省略号
   截掉。现在接口与首屏 SSR 的出口只增一个 `intro` 字段，内容是一整句中文用途
   说明（预算 120 字，仍按完整语义边界收口、不截半句），前端只显示它并放开多行；
   没有中文说明就不摆描述行，不摆「X 开源项目」标签、不摆英文原文。星标 / 日均 /
   涨速 / 语言 / 来源仍由下方徽章展示，不再用文字重复叙述一遍。`desc` 作为气泡
   抽取用的内部字段保持不变，磁盘缓存格式不变，本改动不产生任何外部请求、
   不新增抓取、不改动新闻卡片版式。真实缓存全池 39 条体检：元信息残留 0、
   半句残缺 0。
   【十五修】**上榜准入补一条「站方简介非空」**：用户质疑「没有介绍，怎么上的榜？
   用户为什么会选择？」——原准入只看时间窗口、星标/涨速、题材闸门与链接合法，
   `description` 仅用于敏感词扫描与译文，作者没填简介的仓库照样占位，用户点开
   也不知道项目干什么。现在 `_oss_items_from_payload` 源头就不收空简介；磁盘
   老缓存残留的空简介条目由出口 `_oss_display_rows` 二次过滤并重排名次，整池
   都无中文说明时保留原榜，保证「软件」栏三档入口不整块消失。实测这 3 条在
   GitHub 官方接口 `description = None`，本机 `desc_en` 也为空，因此**不抓
   README、不硬编中文、不新增任何外部请求** —— 仍只用搜索接口本就返回的
   公开简介，不触碰 README 正文，第 7.3 节「只聚合公开标题与链接 + 站方一句
   简介、不转载正文」的口径不变。气泡链路读内存快照，不经过展示过滤，
   「轮播必出开源」不受影响。真实缓存月榜 20→19、周榜 19→17、速榜 0，
   名次全部连续。
   **气泡正文口径（2026-11-12 用户定）**：开源条正文**全中文**——一句话说明这个项目
   是干什么的（取自站方 desc 的中文用途说明，去括号、按语义收口、不截半句）+ 日增星数，
   不夹英文仓库名、建库日期、原因括号、引导语或「每 N 小时一批」；引导语交给气泡自带的
   「打开」按钮。原长文案在本机 19 条真数据上 18~19/19 被两行版式收成「…」。正文若仍装不下
   （极长的英文产品名），绘制时按 font_title → font_msg → font_meta 自动退字号，宁可字小
   一号也不在末尾收省略号；不新建字体资源、不改新闻标题版式。
   **同一件事多网站不重复（2026-11-12 八修）**：事件记忆窗口 6h → 26h（与播过名单对齐，
   容量 400 → 1200），并给此前「只写不读」的开机播报 / 大事提醒补上播前同事件过滤；
   同一件事带新数字/新序数的后续发展按既有冲突判据放行，不压真新闻。全为本机计算，零外部请求。

**直连与点开是两件事（2026-10-28 实测后写清楚）**：程序自己抓榜、取分享卡都走**直连** ——
`httpx` 显式 `trust_env=False`（第 7.2 节那条口径），不读系统代理，所以**关着狐径这一栏照样出**；
反过来，卡片点开的是 `github.com` 的仓库页，本机要开着狐径才打得开 —— 那一步由用户自己的浏览器
与网络环境决定，本程序不参与、也不记录。

**总开关**：`OSS_ENABLED`（`server.py`「开源热榜」一节）。改成 `False` 三份榜一起消失、
周榜的桌面播报也一并停，不用动任何新闻口径。**已实测**：源码版与打包版都跑通
（本机 2026-10-28 抓到 20 条、题图正常、把接口指向不可达地址后整栏自动收起）；
2026-11-12 只读探测 7 天窗口 HTTP 200 / 3.3 秒；回归测试 `tests/test_oss_board.py`
同时钉住 30 天榜老口径、周榜新口径与涨速榜的并集 / 星每天（星/小时 ×24）口径。

**权利人 / 站方要求移除时怎么办**：走第 1 节写的 Issue 通道，核实后把 `OSS_ENABLED` 改成
`False` 即可整栏下线，一次升级生效，不需要逐条处理。

## 8. 自查方式（可复跑）

仓库自带发版前自检闸门，**克隆后直接跑**（不需要任何本机路径）：

```bash
python tools/preflight_release.py          # 默认项：治理文件齐备 / 版本号一致 / 私人邮箱 0 命中 /
                                           # 栏目与判据回归断言 / 链接与徽章可达 / 线上升级源对齐
python tools/preflight_release.py --e2e    # 追加端到端抓取（真联网，约 1~3 分钟）
```

全绿（允许 `[SKIP]`）才允许发布；出现 `[FAIL]` 一律先修改，再发布。

另外 `tests\` 下还有几条**不依赖网络与时钟**的口径回归，改了相应口径请一并跑：
`test_age_window.py`（新闻时效窗口只有一处口径）、`test_oss_board.py`（开源热榜的榜单口径、
题材闸门、跳转域名收口与前后端接线）、`test_archive_backfill.py`（本机归档）、
`test_balloon_shown.py`（气泡投放记录）。
