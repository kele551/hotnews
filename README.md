## 使用

下载 [最新 Release](https://gitcode.com/kele551/hotnews/releases) 里的 `hotnews-v1.5.9.exe`，双击运行，自动打开浏览器。

- 自动选端口（8000 起，被占则顺延）
- 启动时自动检查更新（可关闭，见 `config.json`）
- 页面右上角「检查更新」手动触发
- 右下角气泡提醒（见下文），点气泡可直接打开对应新闻

> **国内用户请从 GitCode 下载（速度快）**；**三个平台代码一致**：[GitCode](https://gitcode.com/kele551/hotnews)（主源）· [GitHub](https://github.com/kele551/hotnews)（镜像）· [AtomGit](https://atomgit.com/kele551/hotnews)（自动镜像 GitHub，含发行版附件）。老仓库已于 2026-10-17 起停更，只留最后一版、不再放新包，故不附链接。
> 境外仓库国内近期时常连不通，所以下载、提 Issue、看协议这三件日常事**都走 GitCode**；GitHub 只在 GitCode 也取不到时当后备。
> **二进制发行包请从 GitCode（主）或 GitHub（镜像）下载**；三个平台都收 Issue / PR。

每个源都是**实测连通 + 带图**之后才加入的；实测失败的（无法访问、无图、停更）一律没有采用。

> **合规口径（2026-10-09 起）：只用境内站点。** 境外来源一个不留 ——
> 国际新闻也改用**境内媒体的国际版**（CGTN · 中新网·国际 · 凤凰/澎湃/红星/界面 报的国际新闻）。
> 依据、处置过程与自查方式见 [COMPLIANCE.md](docs/COMPLIANCE.md) 第 7 节。
>
> **⚠ 新闻内容源的唯一例外（2026-10-11 用户拍板）：国际娱乐栏接入 2 家境外娱乐媒体。**
> 境内口径下国际娱乐的供给已被实测探到底 —— CGTN 英文文化分区 50 条里判得出国际的只有
> 6 条，放宽时效到 30 天一条不增；CGTN 西/法/阿/俄四语种文化分区各 200 条，各只有 2~3 条
> 娱乐；中国日报 / 环球时报英文 / 新华英文 / 人民网英文 / 中新网英文 / 中国网 的娱乐 RSS
> 全部 404；国内三家娱乐源 33 条里没有一条真国际稿。用户据此拍板接境外源补这一栏，
> 实测 20 家境外候选后只留下**唯一两家能过「每条必须带高清大图」门槛**的：
> **Variety**（10 条全带图）与 **Consequence**（15 条全带图）。
> 约束：只进国际娱乐栏，不动要闻/科技/财经/体育；加主权红线过滤；
> 总开关 `INTL_ENT_OVERSEAS`（改 `False` 即回到纯境内口径）。
> 详见 [COMPLIANCE.md](docs/COMPLIANCE.md) 第 7 节。
>
> **另有一个非新闻性质的境外请求点（2026-10-28 新增）：「开源热榜」栏目。**
> 它不供稿给任何新闻栏目，读的是 **GitHub 官方 search 接口**里"近 30 天新建的公开仓库按累计
> 星标降序"这一份榜，题图用 GitHub 官方为每个仓库现生成的分享卡。只有仓库全名、站方自己写的
> 一句简介、仓库链接三样公开信息，不抓 README、不下代码、每条直达原页面；命中敏感题材的仓库
> 一条都不展示；抓不到就整栏不出现，新闻板块一条不受影响。总开关 `OSS_ENABLED`。
> 登记与约束见 [COMPLIANCE.md](docs/COMPLIANCE.md) 第 7.3 节。

## 国内 / 国际怎么分的

<details>
<summary><b>国内 / 国际怎么分的</b>（点击展开）</summary>


**用站方自己的栏目分类**，不是靠猜关键词：

- 凤凰网文章页的 JSON-LD 里有 `articleSection`（`国际` / `军事` / `台湾`…）
- 只认**已登记的栏目名**；认不出来才退回关键词判定
  （凤凰会把「独家原创」也塞进 `articleSection`，那是内容类型不是栏目，不能盲信）
- 关键词判定是「像国际 **且** 不像国内」才算国际 —— 只判前者会把
  「外交部：美方应慎重处理台湾问题」这类中国官方表态误当成国际新闻
- ⚠ `articleSection` **只决定"国内还是国际"**，从来不参与栏目命名。所以站方给的
  `大陆` / `台湾` / `时政` / `独家原创` 这类取值**不会**被当成栏目名渲染出来；
  栏目只有定稿那几栏（见上面的栏目表）。

国内栏目里判为国际的条目**不丢弃**，转给国际板块：
国内热榜 → 国际热榜；国内头条 → 国际要闻。

热榜条目一律**按时间倒序**，最新鲜的永远在最上面。

## 时效规则

<details>
<summary><b>时效规则</b>（点击展开）</summary>


- **头条 / 热榜：严格当天**（热榜给 24 小时，否则更新慢的榜单会整个消失）
- **垂类（科技 / 软件 / 娱乐）：按各自窗口放几天**
  —— 实测只在当天里筛，会把更新频率低的垂类源整个饿死（软件栏只剩一家）
- **财经在 `CLS_MAX_AGE_HOURS` 里没有条目** → 跟头条一样按「当天 / 24h」收口；
  `_fix_finance_cls` 因此放在时效收口**之前**调用，避免"科技窗口 96h 的股市稿"
  借着旧栏目混进财经
- **绝不伪造时间**：某一版曾用「解析不出时间就当刚刚」，导致旧闻排到热榜第一条，
  已彻底删除。时间一律取自源站或文章页的真实发布时间
- **播报侧另立四条更严的规矩（2026-10-29 用户：「自动这个样式，还在播报一天前的旧新闻，
  一定要定规则：常看常新」）** —— 上面那套窗口是**页面**的口径（页面多留几天没坏处，
  用户会自己往下翻），气泡只往桌面上推一条，旧闻就是"你没在看的新闻"。四条（实现是
  `_balloon_fresh_cut`，常量 `BALLOON_FRESH_HOURS` / `BALLOON_FRESH_PREFER_HOURS`）：
  - **① 24 小时硬上限**：发出来超过 24 小时的稿子一律不播。时间戳脏 / 没时间戳的放行 ——
    判据只挡"能确证是旧的"，不误伤新稿；未来时间戳按 0 算。
  - **② 6 小时优先档**：24 小时内还凑得出满一组（10 条）的 6 小时内的稿，这一轮就**只播**
    6 小时内的 —— 够新就不拿次新的凑数；凑不满才放宽回 ① 的范围。
  - **③ 播过的记 26 小时**，名单落盘（`%LOCALAPPDATA%\hotnews\balloon_shown.json`，写盘按
    60 秒节流、`.tmp` + `os.replace`），**重启也算播过** —— 「轮播轮播，就是不能重复，反复」。
    TTL 和 ① 绑死（`(BALLOON_FRESH_HOURS + 2) * 3600`），不会出现"名单忘了但还在硬上限里"的空档。
    两个场合越过节流当场写盘：用户**双击托盘**那一轮（`_balloon_mark_shown(..., force=True)`）
    和**退出程序前**那一次（`_balloon_shown_flush()`；`os._exit` 不走 `atexit`，不然"看完这组
    就退出"正好把名单卡在节流窗口里，下次开机又播同一批）。
  - **④ 挑不出来就不播**：回执明说「没有新的可播」并解释一句，**绝不拿旧闻填满一组**。
  - **⑤ 三条入口都得过同一把尺子**（2026-10-29 真机验证揪出来的）：播报有三个地方 ——
    刷新后的自动那一轮（`_notify_news`）、每日摘要（`_daily_digest`）、**开机第一轮**
    （`_boot_balloon`）。前两个当时已经接上，开机那条是自己拼池子的，两道闸都没接：
    关机一天再开机，播的正是昨天的新闻，而且开机那 10 条没记进名单，几分钟后
    「更新提醒」还能把它们再播一遍。现在开机轮同样 `_balloon_fresh_cut(...)` +
    `_balloon_mark_shown(..., force=True)`，一条新鲜的都没有就不弹（开机那一下不塞"没有新的可播"）。
  - 每日摘要（`_daily_digest`）只吃 ①、不吃 ② —— 它一天只发一次，要的是"今天有什么"，
    不是"最新的一条"。
  - 实测代价（本机 200 条池子）：① 挡掉 44 条（22%，最旧 45.7 小时），这一轮 68 条候选
    全在 6 小时内（最旧 5.7 小时）。更新慢的站（爱范儿 / 飞象网 / 雷锋网这类一天一更的）
    因此**上屏机会变少**，但它们在页面里一条没少 —— 这条口径的取舍是"气泡宁少勿旧"。
    闸门在 `tests/test_balloon_shown.py`（第 5–9 组 + 开机那条路）与 `tests/test_tray_play_now.py`（4b 真跑）
  - 装好的 exe 上的实测（`verify_fresh_and_styles_on_exe.py`，2026-10-29 第 14 轮）：开机第一轮
    报「挡掉 99 条超过 24 小时的旧闻，另有 81 条让位给 6 小时内的」；连点两次双击托盘，
    两次各播 10 条且**一条都不一样**（名单 20→30→40），播出去的最旧 5.0 小时，全在 ② 的
    6 小时优先档内。判据不是"看它挡了几条"而是"**名单里每一条按被播出去那一刻算都 ≤24 小时**"
    —— 页面池子里查不到发布时间的那几条不计。

## 图片规则

<details>
<summary><b>图片规则</b>（点击展开）</summary>


- 每条新闻**必须有高清大图**，门槛是短边 300；无图一律不上
- **RSS 本身不带图的源**自动去文章页取图：少数派 / 新浪娱乐取 `og:image`；
  中新网系（国际 / 财经）**连 `og:image` 都没有**，按站点规则从正文容器
  `<div class="left_zw">` 里取首图（优先取带「图说」的那张，避免配到相关新闻的缩略图）
- **列表页只给缩略图的源**会把地址改写成原图：国际在线娱乐的卡片图是 512×288
  （短边 288 差 12 像素过不了 300 的门槛），按站方 URL 规则去掉最后一节下发尺寸即可拿到
  991×558 ~ 4052×2278 的原图
- 这类「去正文页取首图」的源**单条限时 3 秒**、结果进缓存（文章元数据 7 天），
  取不到就跳过该条 —— 不让个别慢页面拖住整轮刷新
- **mefcl 例外**：站方题图本身就是 220×150，去正文页也换不出更大的，
  所以给它开了图质豁免（否则整个「软件」栏目会消失）
- 补图名额（一轮 96 条）**按来源轮流分配**，避免条目多的源把名额占满、
  害得别的源整轮补不到图而在页面上消失

## 右下角气泡提醒

<details>
<summary><b>右下角气泡提醒</b>（点击展开）</summary>


自绘窗口，**不依赖系统通知**（Windows 11 且通知总开关关闭时，系统气泡会被静默丢弃）。

一条气泡里滚动播放 **10 条**，每条 **5.6 秒**（一整组约 56 秒）。播到第几条看**底部那排圆点**，
最底下那条细进度条按 5.6 秒一格慢慢收（2026-10-28 改版：原来挤在标题尾巴上的 `(3/10)`
既跟标题抢位置、又会在一行结尾拐弯，很难扫）。

卡片颜色**跟控制台走**：暗色档是深灰卡 + 浅字，亮色档是白卡 + 深字；控制台那五档「主色」
（品牌橙 / 蓝 / 绿 / 紫 / 琥珀）也是同一套，圆点、进度条、标签描边一起换。控制台里切一次主题，
下一次弹出来的气泡就是新配色 —— 页面会把**生效值**回报到 `/api/ui` 存进本机配置，气泡读那份；
没手动切过就按「跟随系统」（Windows 的 `AppsUseLightTheme`，和浏览器 `prefers-color-scheme` 同一条判据）。

**播报样式有三种，用户自己选**（2026-10-28 加；2026-10-29 按用户「播报样式太多，可以精简成三个
样式，聚光灯必须留下，你自己衡量」从五档收到三档。配置键 `ui.balloon`，取值
`auto` / `live` / `spot`，常量 `BALLOON_STYLES`）。入口**只在托盘右键「播报样式」**
（命令 id 从 `_TRAY_CMD_STYLE_BASE = 30` 起排：30=自动 31=速递 32=聚光灯），控制台页面上没有这个下拉 —— 用户点名
「样式选择的入口放在右下角菜单里吧」，页面那块地方留给内容。默认 `auto`：**本机缓存里拿得到题图**
走聚光灯、拿不到走速递（判的是文件不是 URL，见下面「用户点名哪档就是哪档」）。
**选完当场换一组** —— 正在播的那一组被掐掉，不让人等完剩下的五十多秒
（见下面「谁开口才打断」）。

| 样式 | 键 | 版式 | 认它的地方 |
|---|---|---|---|
| 自动 | `auto` | 唯一会分流的一档：本机缓存拿得到题图 → 聚光灯，拿不到 → 速递 | `_balloon_pick_style` |
| 速递 | `live` | 快讯推送：标题逐字打出（打字机），右上角会跳的波形 | `_paint_live` |
| 聚光灯 | `spot` | 整张题图当底图由远及近渐进推近，文字压在图上；**图还没下载回来时画一张同版式的自绘底，不退档** | `_paint_spot` / `_paint_spot_backdrop` |

砍掉的两档为什么（判据在 `tests/test_balloon_styles.py` 第 1 / 5 / 5c 组）：

- `card`（卡片）—— 标题字号统一成聚光灯那一档之后，它和 `live` 就是**同一张版面**，只差有没有
  打字机和声波，留在菜单里等于给用户两个几乎一样的名字。**版面代码没删**：`self.style == "card"`
  是 WM_PAINT 那条 fall-through（不启动 40ms 动画计时器），现在只在版式解析抛异常时兜底 ——
  静态一张卡，字一定在。
- `tv`（新闻条）—— 整档删除（`_paint_tv` 连它专用的那支 19.2 的 `font_hl` 一起删）。它是唯一
  一支标题字号不跟共用的（标题带只有 302 宽：右边让给题图、底边让给跑马灯），底带那条滚动字幕
  还反复和悬停的[关闭][打开]抢位置（当初专门加过让位逻辑）。删掉之后"换样式 = 换字号"这件事
  在代码里再也发生不了。
- 本机配置里可能还写着已经下线的取值（用户以前手选过）：走 `BALLOON_STYLE_LEGACY` 归位
  （`card`→`live`、`tv`→`auto`），**不当脏值一律回落自动** —— 选过卡片的人本来就爱干净的文字卡。

（原来还有一档「方块字轮播」`flap`，2026-10-28 用户看过实拍后否掉：「方块式字体的轮播，
效果不好，这的样式取消」，已整条链路删除。）

**字为什么这么画**（2026-10-28 连着四轮实拍调出来的，改之前先看这段）：

- 气泡是 `WS_EX_LAYERED` + `UpdateLayeredWindow` 的**逐像素透明**窗口，所以字体**不许用
  ClearType**（`iQuality=5`）：ClearType 把笔画边缘的灰度藏在 R/G/B 子像素里，DWM 再拿 alpha
  和桌面混一次就把子像素排列打散了，字边带橙/蓝毛边 —— 用户口径就是「字体发虚」。
  每一档字体统一 `ANTIALIASED_QUALITY(4)`，`tests/test_balloon_layout.py` 里那条闸门数的是
  「有几支 `CreateFontW` 就必须有几处质量参数、且全是 4」，加一档减一档都不用改闸门。
- **标题只有一支字体**（2026-10-29 用户：「这个字体换成，聚光灯式的字体，包括卡片式字体，
  自动的字体都换成聚光灯式的」）：`font_title` = `BALLOON_HEAD_PX` 21.6 逻辑像素 / 真粗体 700
  （原 `font_spot` 改名），速递 / 自动 / 聚光灯和退居兜底的卡片版都用它。以前速递 18/600、
  卡片 16/600、新闻条 19.2/700 —— 同一组新闻换一档样式标题就换一号字，用户读到的意思是
  "这几档不是一回事"。撑得住是因为版面一起改了：标题带从「右边让出 84 给题图、两行 ×24」
  变成「整行 436、两行 ×30」，题图挪进底部左角 58×58，来源行和分页点跟着让出题图那 58+16 宽。
  另一处关键是 `_fit_lines` 的单位 bug：`_text_w` 返回**物理**像素、版面常量是**逻辑**像素，
  直接比就等于每行按 1/缩放比（125% 上少 20%）提前砍字。本机 200 条真标题两行装不下的
  从 81 条（40.5%）降到 14 条（7%）—— 字变大，被砍掉的标题反而更少。
  闸门在 `tests/test_balloon_styles.py` 第 5c 组（含"19.2 那支不许回来"）和
  `tests/test_balloon_layout.py` 第 1 组（标题带与题图/按钮的真矩形不相交，186 组尺寸矩阵）。
- 缩放屏上字号按**物理像素**算（2560×1440 @125% → `s=1.25`），不然 11.5px 的小字会糊。
- `txt2` / `txt3` 在 `_balloon_palette()` 里往 `txt` 的方向提一档再发出去：控制台那两档是给
  **坐着凑近读的网页**定的（亮色 `--txt-3` 在白卡上只有 2.9:1），气泡离一臂远、字又小，
  原样抄过来就是「看不清」。提完亮 5.58:1 / 6.49:1，网页那边不动。
  闸门是 `tests/test_balloon_layout.py` 第 2b 组，按 WCAG 算对比度，不写死色值。
- GDI 没有渐变，压暗层只能借 GDI+：`GdipCreateLineBrushI` 的 mode 只认 0/1/2/3，
  之前写死 4（非法参数）→ 返回错误、笔刷是 `None`，**聚光灯的压暗层一帧都没画过**而且没人发现
  （错误被 `if not br: return` 吞了）。现在 mode 对了，并且失败会 `print` 一次警告。
- 压暗层补上之后又翻过一次车：为了救白字把标题带压到 226~246/255，图的下半截基本成了纯黑，
  聚光灯退化成"黑底白字"，而这档存在的理由本来就是图好看（用户：「图背景样式还要改进一下，
  图片都看不清了有些」）。现在的分工是**很轻的一层整卡 veil（46/255）+ 顶/底两条渐变**
  （顶带 y=0→46 遮 150→0，底带 56→卡底遮 0→78→148→212）**+ 白字外圈 8 个方向各描一遍黑**
  （`_dt_shadow(halo=1)`）：压暗只压高光，边缘对比交给贴着笔画的描边。代价是每条标题多画
  8 次 `DrawTextW`，只在动画帧和换条时发生。叠出来的实际遮光是：卡片顶沿 196、**标题带那一带
  只有 72~135**、字压在图最亮处时靠描边站住。
  闸门在 `tests/test_balloon_styles.py` 第 5 组：按 y 把三层压暗**叠起来算实际遮了多少**
  （卡片正中 ≤110、最上沿 ≤200），不再盯"字面最大 alpha ≤190" —— 那条老判据会把用户当天
  为「这种模式字体不清楚」调出来的一档当成回归（那一档底部峰值是 212，落在卡片最下沿、
  不在标题带上）。

**谁开口才打断**（2026-10-28 用户：「切换样式模式，播报暂停了一分钟」）：队列原本只在
"没在播"时取下一组，而一组是 10 条 × 5.6 秒 = 56 秒 —— 从托盘选完样式，新的一组排在正在播的
那一组后面，用户看到的就是"点了没反应，一分钟后才换"。现在 `_show_toast_list(entries, replace=True)`
在队列锁里置一个 `BALLOON.interrupt` 标记，**掐窗口的动作仍由气泡自己的消息线程做**
（那几个 `SetTimer` 是它开的，跨线程 `KillTimer`/`ShowWindow` 是不讲理的），下一次 300 毫秒
轮询发现标记就先 `_dismiss` 再开新的。只有三条"人主动开口"的路传 `replace=True`：托盘选播报样式、
托盘「立即轮播一轮」、双击托盘图标；**自动那一轮照常排队** —— 正看着的东西被后台刷新顶掉，
比等半分钟更烦人。实测（装好的 exe，`E:\Qdoer\tmp\ossbuild\verify_installed_spot_swap.py`）：
卡片组正在播第 1 条时换聚光灯并催一轮，**0.38 秒**新样式接管。两道闸门盯着这条链：
`tests/test_balloon_styles.py` 第 6 组看**代码形状**（只有 `replace` 置标记、掐窗口只发生在气泡
自己的线程、标记用完就清、没有任何调用点硬写 `replace=True`），`tests/test_tray_play_now.py`
第 4b 组**真跑几轮** `_notify_news(force=True)`，断言每一轮真播出去时 `replace=True` 一路传到
`_show_toast_list`、而一条没播出去的那两轮不喊掐 —— 光看代码有这个参数不够。

**用户点名哪档就是哪档**（2026-10-28 用户：「图片样式，会出现没有图片的样式」）：题图是
**边播边后台补下**的，实测本机池子 307 条 **100% 都带图 URL**，但开播那一刻缓存只命中约 48%
（缓存目录 236 个文件），慢的那几条十几秒才到。旧代码有两处会在这时候"自作主张"：
`_balloon_pick_style()` 不分auto还是手选，只要没图就返回 `live`；`_paint_spot()` 画不出底图时
再 `self._paint_live(...)` 退一档 —— 于是**一组里聚光灯 / 速递来回跳**，用户看到的就是"样式自己变了"。
现在两条都堵上：

- `_balloon_pick_style(raw, has_img)` 只在 `auto` 那一档分流，**手选的档一律不退**；
  `auto` 的判据也从"有没有图 URL"换成"**本机缓存里有没有这个文件**"（这些站每条都带 URL，按 URL 判等于不判），
  `GET /api/ui` 报的 `resolved.balloon` 用同一条判据，排查时不会两套口径；
- 没图时 `_paint_spot_backdrop()` 画一张自己的底：主色直接进底渐变（上半截给到 58% 的主色，
  五档主色一眼能分辨）+ 右上角一道斜着下来的主色光洗 + 标题那一带一片软白光池 +
  一道 5.2 秒走完的斜光柱（和有图那版推近**同一条时间轴**，两种底来回切节奏一致）。
  压暗、描边、字位和有图版**共用同一段代码**，所以图在后台下好了下一帧自然盖上，位置一个像素不动；
- 唯一保留的退路是 GDI+ 起不来（`self.gdip` 为 `None`，渐变画不了）—— 那是"环境坏了"，
  退成速递比退成一张纯黑方块强，和"这条没图"不是一回事。

实测（装好的 exe，`E:\Qdoer\tmp\ossbuild\verify_spot_noimg_on_exe.py`）：把缓存整个挪开重启，
发一条等价于双击托盘的消息让 exe 自己播一组，**38 次 `/api/ui` 轮询 `resolved.balloon` 全是
`spot`**；实拍两张分别在 2.0 秒（无图，聚光灯版式完好）与 8.0 秒（图下回来了，同一版式）。
无图那张的标题带最亮处相对亮度 0.0742 → 白字 **8.46:1**，比有图版最亮那批真实题图（0.985，
靠 8 向描边救）还宽松。闸门在 `tests/test_balloon_styles.py` 第 2 组（手选的档不退；2026-10-29
精简成三档后，这一组还钉"已下线的老取值喂进分流也只能落到活档"）
与第 5b 组（底的形状：主色真的进渐变、裁剪收得回来、`_paint_spot` 里只剩那一条环境性退路）。

- 头条那条显示 **`【头条】`**，画成页面 `.tag.fresh` 同款的**红色着色标签**（字色 + 混色描边 +
  混色底）；2026-10-28 起不再整卡换红底 —— 页面没这么干，气泡换了就成两套设计；
- 热榜那条显示 **`【热榜】凤凰网热榜 第4`**（用户点名「气泡里的热榜条目必须带出处」）；
- 国际条目显示 **`国际·要闻`** 这类（带频道前缀，跟国内同栏目区分开）；
- 其余就是栏目名本身：科技 / 财经 / 娱乐 / 软件。

名额**按栏目配额**挑（用户逐条定稿）：**头条 2 + 科技 2 + 财经 2 + 娱乐 2**，
剩下的 2 个席位按 **软件 → 热榜 → 国际 → 其他栏目** 补足；哪一栏当期没货就用别的栏目补满 10 条。
日志按栏目报数：`[ok] 更新提醒：滚动播放 10 条（头条2/科技2/财经2/娱乐2/软件1/热榜1）`。四条规则：

- **同一来源只取一条** —— 不然更新最勤的站点（快科技、IT之家）会把 10 个位置全占掉
- **只播中文条目**，国际新闻优先取境内媒体（凤凰 / 澎湃 / 红星 / 中新网·国际）报的，
  CGTN 那种英文条目排在后面（翻译没跟上时不会顶到前面去）
- **播过的不重复** —— 记下已播条目，一轮播完才开新一轮
- **每条停留 5.6 秒**：10 条 × 7.2 秒 = 72 秒一组实测太拖（用户多半播到第 4~5 条就切走了），
  3 秒又读不完一行标题；5.6 秒正好读得完一条（含栏目行），一组 56 秒

鼠标移到气泡上会浮出「打开 / 退出」两个按钮，并且**暂停自动关闭**（不然 5.6 秒来不及点）。
两个按钮固定在**底部操作行**最右侧，正文带到它上面就结束 —— 2026-10-28 版式重排后，
按钮在几何上不可能再压到文字（用户原话：「打开和退出，两个按键，已经遮挡文字」）。
**点气泡正文或「打开」直接打开当前那条新闻的原文**（没有链接时才回落到程序首页）。

| 类型 | 触发 |
|---|---|
| 新闻更新 | 有新条目就弹，间隔可设 **5 / 10 / 30 / 60 分钟**（默认 10；托盘右键「轮播间隔」）；另受**常看常新**四道闸管着 —— 超 24 小时不播、够新时只播 6 小时内的、播过的记 26 小时（见上面「时效规则」） |
| 手动一轮 | 托盘右键「立即轮播一轮」或**双击托盘图标**：不等节流、不看夜间免打扰，但**绝不重播** —— 没有新条目就回一句「没有新的可播」，不拿旧的凑数 |
| 新闻大事 | 标题命中大事关键词，或同一件事被 ≥3 家不同来源报道 |
| ★ 我的软件被发布 | 标题命中 `MY_SOFTWARE_KEYWORDS`（壁纸助手 / 狐径 / FoxPath / kele551） |

后两类**不做时间节流**。

**「工作时不打扰」这道闸只留两种状态**（2026-10-28 立，2026-10-30 收窄）。判据不自己发明，
问 Windows：`SHQueryUserNotificationState`（`_quns_state()`），命中 `_QUNS_HOLD` 里那两条就不弹这一轮 ——
**1 锁屏/休眠**（弹了没人看见）、**4 投影/演示**（真会盖住画面）。2（BUSY 勿扰/全屏程序）、
3（D3D 全屏游戏）、6（系统静默时段）以前也挡，代价实测过一次：系统报一次 2，
自动播报连挡 8 轮、**56 分钟一声不响**（10:21~11:01），而长时间全屏干活正是这个程序的主用法，
所以上面那张表的「有新条目就弹」现在对全屏场景也成立。开关是 `notify.hold_on`（默认开），
两个入口写同一个键：托盘右键「工作时不打扰（锁屏 / 投影演示时让路）」、控制台「程序设置」同名一项。
**手动那一轮从来不看这道闸**（`force=True`）。跳过不消耗节流窗口、不写播过名单，所以条目不会丢，
下一轮刷新自然带着同一批再来。排查时看决定链：`GET /api/notify`（也要 `x-hn-token`）的 `balloon`
数组带时间戳，且每条都写清「系统状态码 + 当时前台窗口是谁」（`_hold_note()` / `_foreground_hint()`）。

</details>

## 自动更新机制

<details>
<summary><b>自动更新机制</b>（点击展开）</summary>


> **默认全自动、不弹确认框**：启动后静默检查 → 静默下载 → 验签 + 校验 sha256/尺寸 → 自动替换运行。
> **只有出问题才提示一次**，并且始终保留旧版本可继续使用。详见下面「升级体验」一节。

- 启动时后台静默检查 `version.json`（国内优先走 GitCode）
- 更新源按顺序试两个地址，**每一个都必须通过 Ed25519 验签**才被采用：
  1. `https://gitcode.com/api/v5/repos/kele551/hotnews/raw/version.json?ref=main`（GitCode 主源）
  2. `https://raw.githubusercontent.com/kele551/hotnews/main/version.json`（GitHub 兜底）
- 发现新版 → 后台下载 exe → 校验 sha256 → 自动替换重启（替换前还会再校验一次尺寸与 sha256）
- 也可点页面「检查更新」按钮手动触发（手动触发同样不再弹确认框）

### 升级体验：默认自动、失败才提示

| 情形 | 行为 |
|---|---|
| 有新版（`auto_update=true`，默认） | 静默下载 + 验签 + 校验；**不弹任何确认框**；校验通过后自动替换并重启 |
| 后台静默实例（开机自启那种，`--silent`） | 校验通过就**立刻**替换重启，用户完全无感 |
| 前台实例（用户正在看页面） | 不打断：**退出程序时自动完成替换**（页面「退出程序」/ 托盘「退出程序」都会先装再退），下次启动就是新版 |
| 下载失败 / 验签不过 / sha 不符 / 替换没成功 | **只提示一次**：一条气泡说清原因 + 一句怎么办；**旧版本保持可用，程序不会消失** |
| `auto_update=false` | 只提示「发现新版本 vX」，**不下载、不自动升级**；由用户自己点「检查更新」 |
| `enabled=false` | 连检查都不做 |

配置写在 `config.json`（可被 `%LOCALAPPDATA%\hotnews\config.local.json` 覆盖）：

```json
{ "update": { "enabled": true, "auto_update": true } }
```

> **升级的安全底线与维护者须知**（fail-closed 的六条底线、`version.json` 完整版的字节口径与签名、
> 发布新版本踩过的坑、为什么禁止强推、以及发完怎么一条命令复核线上 `tools/verify_release.py`）见
> [CONTRIBUTING.md](docs/CONTRIBUTING.md) 第 5.1 ～ 5.3 节。

</details>

## 仓库约定

- 行尾：入库与检出**一律 LF**（`.gitattributes` 的 `* text=auto eol=lf`），只有 `说明.txt` 例外、保持 CRLF。
- 关键词表放在 **`data/keywords.txt`**（国家 / 地区 / 机构 / 赛事…以纯数据形式），`server.py` 里只有加载函数 `_load_keywords()`。
- 打包前先核对清单：`python build.py --list` —— 清单里不该出现历史 exe、调试快照、PyInstaller 中间目录。

> 三条约定的完整说明（当年行尾错乱的来龙去脉、关键词表为什么搬出代码、打包排除规则的细节与例外）见 [CONTRIBUTING.md](docs/CONTRIBUTING.md) 第 3.5 节。

## 路线图（Roadmap）

<details>
<summary><b>路线图（Roadmap）</b>（点击展开）</summary>


下面是**真实在做、做完就会回来更新这一节**的方向，按优先级排列：

1. **继续补已实测可用的源** —— 按「真连通 + 带图（短边 ≥300）+ 有当天或近日内容」三条实测标准补源，
   让每个栏目稳定 ≥3 家网站。
   ★ 当前最缺的是 **国内「财经」（2 家）与「娱乐」（3 家，且新浪娱乐首页把当天稿子基本放在
   5 天窗口之外）**：境内财经/娱乐类站点实测下来**没有一家给出可直接用的 RSS 或干净的列表结构**
   （试过的清单见 [CONTRIBUTING.md](docs/CONTRIBUTING.md) 第 4.5 节「实测失败、没有采用的源」），
   所以先如实留成 2~3 家。没实测过的源不会写进来。
2. **移动端局域网查看** —— 让手机在同一个局域网里也能打开页面看新闻。
   现状：程序默认只监听 `127.0.0.1`，要局域网访问得用 `--host 0.0.0.0`；
   而「退出程序 / 立即更新 / 开机自启」这三个有副作用的按钮**只允许本机操作**，
   非本机访问会返回 403（见 [SECURITY.md](docs/SECURITY.md)）。
   所以要做的不是简单放开监听，而是：为小屏做自适应布局，
   并把「只读浏览」与「本机管理」在界面上分清楚。
3. **源可用性自检面板** —— 现在查「某个源怎么没内容」得开命令行跑 `check_sources.py`
   （打印每个 Region 的条数、最新 / 最旧时间、带图数、分类分布）。
   计划把它搬进页面做成可视化面板：一眼看出哪个源当前抓不到、哪个源不带图、哪个源停更了。

**维护原则**（比上面的清单更重要）：

- **不为修 bug 单独发版** —— 修复先攒着，跟下一个真功能版本一起发。
- **没测过的东西不交付** —— 发布前跑完整自检（冷启动、完整升级演练、失败分支、版本一致性），红一条不发。
- 线上每发现一个新问题，就把那一幕补成一个检查项，让同一个坑不可能踩第二次。

</details>
